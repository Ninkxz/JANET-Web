# Fable 5 Review - JANET Web - 2026-07-07

JANET Web is in strong shape. All 51 `.ps1`/`.psm1` files parse clean under Windows PowerShell 5.1 and every one carries a UTF-8 BOM; the full Pester suite passes **235/235**; the SPA has real XSS discipline (grid cells render via `textContent`, free-text goes through `esc()`/`escHtml()`, confirm-dialog `bodyHtml` callers escape); the server has a constant-time token compare, a resolved-path traversal guard with a trailing-separator prefix check, hardened upload-name sanitization (traversal, invalid chars, reserved device names), CSV-injection protection in the logging bridge, atomic temp+swap writes, and a job reaper with correct cancel semantics. Destructive actions are double-gated (browser gate mirrored by the authoritative server-side ack+cred check, including the ACAS by-id actions that bypass the manifest). What keeps this review off a clean GREEN is one destructive-safety gap (no dispatcher self-guard on the WPT/ACAS reboot paths, a guard the Restart and WinUpgrade tools already have) and one systematic correctness bug (nine of ten WPT DNS-mismatch guards false-abort every IPv4-literal target). Both are contained, well-understood, and cheap to fix. Overall rating: **YELLOW** (two fixes away from GREEN).

## Findings

**[P1]** `modules/JanetWeb.wpt.psm1:1665-1688` (WptRebootBlock), `:1694-1756` (WptRebootScheduleBlock) and `modules/JanetWeb.acas.psm1:1675-1738` (AcasRebootWorker) - **no dispatcher self-guard on reboot paths.** The Restart tool drops the JANET box from every wave (`JanetWeb.restart.psm1:1276-1287`, audit#10, with a full identity set: name/FQDN/IPs/localhost) and WinUpgrade ports the same guard (`JanetWeb.winupgrade.psm1:282-309, 1796-1806`), but WPT "reboot selected"/"schedule reboot" and ACAS "reboot-selected"/"schedule-reboot" will happily reboot the machine the server is running on. This is realistic, not theoretical: the dispatcher workstation shows up in WPT bulk-scan grids and in imported ACAS CSV host lists, and "select all pending-reboot hosts -> reboot" includes it. A self-reboot kills the server mid-wave, aborts the remaining hosts, and loses in-flight jobs and their audit events. The DNS-mismatch guard does not help (dialing yourself matches). Fix: port the restart pattern - build the local-identity set once at dispatch, drop self-targets with a warn event - into the WPT reboot dispatch and the ACAS reboot fan-out.

**[P2]** `modules/JanetWeb.wpt.psm1` - **9 of 10 DNS-mismatch guards false-abort every IPv4-literal target.** The guard computes `$targetShort = ($Computer -split '\.')[0]`, so target `10.20.30.40` becomes `'10'`, which can never equal the remote `$env:COMPUTERNAME` -> guaranteed "DNS mismatch ... ABORTED". Affected sites: WptScanBlock `:1564` (bulk-scan rows error out), WptPatchBlock `:1611`, WptRebootBlock `:1677`, WptRebootScheduleBlock `:1703/1708`, WptKbInstallBlock `:2306`, WptRegApplyBlock `:2759`, WptSccmInstallBlock `:3302`, WptSoftwareUninstallBlock `:3584`, WptAppActionBlock `:3817`. Only WptMaintLockBlock `:3072` has the IPv4 skip (`-notmatch '^\d{1,3}(\.\d{1,3}){3}$'`). Ironically the fixed siblings all cite WPT as their source: `JanetWeb.acas.psm1:1587/1695/1722`, `JanetWeb.upr.psm1:876`, `JanetWeb.winupgrade.psm1:741`, `JanetWeb.restart.psm1:367` (audit#9) - the most-used tool is the one that never received the fix. It fails safe (aborts, no wrong-box action), but WPT is functionally dead for IP targeting. Fix: copy the one-line skip into the nine sites; add an IP-target case to `tests/Wpt.Guards.Tests.ps1`.

**[P2]** `server/JanetWeb.Server.ps1:596-601` - **schedule-arming gate only covers destructive actions.** `POST /api/schedule` requires the admin session (ack + cred) only when `$sDestructive`; any token-holder can arm a NON-destructive wave - including a `recurrence='daily'` one (`:608`) - with no session at all, and the poller (`:300-356`) will fire it unattended forever. A recurring daily WPT bulk-scan armed once is exactly the "auto fleet-scanning" the JANET operating model rejects (see Operating-model fit). The destructive path is properly fail-safe (`:599` arm gate + the live-session 403 at fire time `:349-350`), the non-destructive path has no human tether at any point. Fix: require the admin session to arm *any* schedule, and consider restricting `recurrence` to one-shot (`none`) for non-destructive actions.

**[P3]** `server/JanetWeb.Server.ps1:363` vs `:1332-1336` - **scheduler poller runspace is never stopped or disposed.** The `finally` block closes tool runspaces and the listener but not `$state.SchedPoller`. After Ctrl+C the `while($true)` poller keeps running inside the still-open `-NoExit` console process, re-reading `JanetLocal\schedule` every 15 s with the now-stale token. If JANET Web is relaunched (same port), the orphan's 403s stamp armed schedules `blocked`/`error`, racing the live poller for the same files. Fix: `$schedPs.Stop(); $schedPs.Dispose(); $schedRs.Dispose()` in the finally.

**[P3]** `server/JanetWeb.Server.ps1:1073` - **malformed JSON action body is silently swallowed** (`catch {}`), so the action runs with an *empty* params table instead of returning 400. A truncated/garbled POST body turns "patch these hosts" into a params-less invoke that surfaces as a confusing engine-side required-input error (or an engine running on defaults). The schedule route already does this right (`:585` returns 400 on bad JSON). Fix: mirror that here.

**[P3]** `server/JanetWeb.Server.ps1:336-348` - **the poller stamps "fired ok (HTTP 200)" on job *acceptance*, not outcome.** The action route returns `{jobId}` immediately; the poller never polls `/api/job/<id>/events`, and a recurrence advances regardless. An armed nightly wave that starts-and-fails every night reads "fired ok" forever in the schedule ledger. Fix: persist the returned `jobId` into the schedule JSON (audit trail), and optionally check the job's terminal status before writing the note.

**[P3]** `server/JanetWeb.Logging.ps1:50-55` with `server/JanetWeb.Server.ps1:846-848, 866-872` - **`Resolve-JanetWebToolName` strips `[\\/:*?"<>|]` but not `..`**, so `GET /api/logs/tail?tool=..` reads `<logroot>\..\<userFolder>\<month>_detail.csv` one level above the log root. Impact is negligible (token-gated loopback, fixed filename suffix, runs as the same user), so this is hardening only: reject dot-only ids or allowlist `tool` against the registry ids. Related nit: the token is also accepted via query string on every API route (`:434`); it is only needed for the bootstrap page load (the SPA strips it, `web/js/shell.js:29-30`), so `?t=` could be ignored on non-bootstrap routes.

No further P1s found. Checked and clean: token compare is constant-time (`Server.ps1:436-439`); static-file traversal guard resolves and prefix-checks with a trailing separator (`:401-410`); underscore dev assets 404 (`:396-399`); upload filename/subdir sanitization covers traversal, invalid chars, and reserved device names (`:894-910`) with a bounded stream copy against lying Content-Length (`:918-927`); the pre-token `GET /api/report-preview` is a deliberate one-shot GUID capability with TTL and delete-on-read (`:423-431`); secureboot's password-bearing payload single-quote-escapes both baked literals, self-deletes on the target, and the operator input is allowlist-validated upstream (`JanetWeb.secureboot.psm1:443-449, 345-348`); shutdown warn-text is sanitized before `/c` (`JanetWeb.acas.psm1:1678-1683`) and the VBS popup body is control-char-stripped, capped, and quote-folded (`JanetWeb.wpt.psm1:1722-1727`); MSI copies are SHA256-verified before execution (`JanetWeb.pkginstall.psm1` deploy block); CSV fields are formula-escaped (`Protect-JanetWebCsvField`); the events poll snapshots under the ArrayList SyncRoot (`Server.ps1:1281-1287`).

## Operating-model fit

The code sits at the right altitude almost everywhere. JANET Web is an operator-launched, loopback-only, per-wave ACTION surface: every fan-out is triggered by hand against an explicit host list, engines are remediation-side (patch push, KB install, reboot, uninstall, jar-swap, registry apply, maintenance lock), and the recon that exists (WPT bulk scan, sysadmin sweeps, biosfirmware scan, C2C readiness) is one-shot, operator-initiated, and feeds a fix decision - that is the Tanium/ACAS-identify -> JANET-does-the-fix division of labor working as intended. The hub dashboard is explicitly flat-files-only ("never touches a host, never spins a runspace", `Server.ps1:656-663`), which is exactly the right instinct.

One drift flag: the **off-hours scheduler's `daily`/`weekly` recurrence** (`Server.ps1:338-347, 608`). Arm-once/fire-once is squarely in-model (it is the RemoteScheduledPush pattern - a human decides a specific wave, it fires once, off-hours). Arm-once/fire-*forever* is standing automation. For destructive waves the model survives because the wave only fires while an admin session is live in this server process (fail-safe on reboot/restart); but for non-destructive actions there is no gate at arm time or fire time (the P2 above), so a recurring scan wave is literally unattended fleet-scanning - the thing JANET deliberately is not. Recommend either dropping recurrence for non-destructive actions or gating all arming behind the admin session and documenting recurrence as a destructive-wave convenience only.

## Consistency / dead-code / docs

- **Guard parity is the main inconsistency**: the IPv4-skip and the self-guard each exist in some tools and not others (detailed above). The codebase's own comments cross-reference the guards between tools, so the divergence reads as missed back-porting, not intent.
- **Stale README**: `README.md` instructs re-forking engines from `fork-source\` (no such folder in the repo anymore) and says to "Reference it in place at `X:\J.A.N.E.T ONE\`" - JANET ONE was retired and its folder deleted (archived 2026-07-06). Same staleness in `docs/HANDOFF.md` ("re-forked fresh from the desktop `fork-source/Tools/*.ps1`").
- **Server header route table is out of date**: `server/JanetWeb.Server.ps1:13-22` lists 8 routes; the file now serves ~20 (`/api/status`, `/api/session/*`, `/api/schedule*`, `/api/dashboard`, `/api/upload`, `/api/report-preview`, `/api/logs/*`, `/api/target-groups`, pkginstall helpers).
- **TWO-era branding residue** after the JanetTwo -> JanetWeb rename: `Resolve-JanetWebToolName` falls back to `'JANET-TWO'` for an empty tool id (`JanetWeb.Logging.ps1:53`), env var `JANET2_PACKAGES_ROOT` (`Server.ps1:85`), Add-Type namespace `JTwo` (`JanetWeb.Auth.ps1:57`), launcher sentinel `JANETTWO_CONHOST` (`JanetWeb.Internal.ps1:57-58`). The env/sentinel names are functional back-compat, so rename deliberately or leave a comment saying they are frozen.
- **Doc accumulation**: `docs\` carries nine per-session handoffs (`SESSION-2..7-HANDOFF.md`, `HANDOFF.md`, `NEXT-SESSION.md`, `SESSION_HANDOFF_2026-06-29.md` duplicated at repo root). History belongs to git; a single current HANDOFF plus the ui-specs would do.
- **Not dead code**: `modules/JanetWeb.beta.psm1` (empty `actions = @()`, `:28`) is the intentional Beta staging placeholder and documents its own add-a-section recipe - fine as is. Tests using `Invoke-Expression` on source excerpts (`tests/FixVerify2.Tests.ps1:252` etc.) are test-harness-only and acceptable.
- **Tests**: 235/235 green on this box (Pester 3-compatible syntax throughout). Guard behavior is test-backed (`Wpt.Guards`, `Restart.Guards`, `Server.Gate`, `Server.Scheduler`) - which is exactly why the two guard gaps above should land with tests.

## Recommendations

1. **Port the dispatcher self-guard** (restart `:1276-1287` pattern) into the WPT reboot/schedule-reboot dispatch and the ACAS reboot fan-out. (P1)
2. **Add the IPv4-literal skip to the nine WPT DNS-mismatch guard sites** (copy MaintLock `:3072` / acas `:1587`), with an IP-target Pester case. (P2)
3. **Close the scheduler gate asymmetry**: admin session required to arm any schedule; reconsider recurrence for non-destructive actions (operating-model drift). (P2)
4. **Server hygiene trio**: stop/dispose `SchedPoller` in the finally; return 400 on malformed action bodies; record `jobId` (and ideally terminal status) in fired schedule files. (P3)
5. **Doc pass**: refresh README/HANDOFF (fork-source and JANET ONE references), update the Server.ps1 header route list, prune old session handoffs. (P3)
6. Optional hardening: allowlist the `tool` query param on the log routes; ignore `?t=` token on non-bootstrap API routes. (P3)
