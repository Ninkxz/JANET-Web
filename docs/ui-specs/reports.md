# JANET TWO - UI Rebuild Spec: reports

> Engine is re-forked from `fork-source\Tools`; THIS is the faithful FRONTEND to reproduce (screens, run model, live activity view).

## Summary

The J.A.N.E.T. Reports Tool is a single-window WinForms desktop app (1400x950, dark theme, gold/purple accents) for ingesting ACAS/Nessus vulnerability scans and cross-referencing them against patch status. It uses a fixed 180px left SIDEBAR of nav buttons (NOT a TabControl) that swaps full-screen content Panels in a Fill content area; a persistent timestamped activity log lives at the bottom of the sidebar and every action writes to it via a global Log() function. The operator's loop: import ACAS findings (CSV/TSV/.nessus, de-duped by Hostname|PluginID), parallel-ping hosts into Online/Offline buckets, triage findings in a color-coded DataGridView (filter by host/severity/category/status + live search), batch- or selection-mark findings as Patched (with a Patched-By/Date dialog) or NOT OUR PATCH, watch a Dashboard of metric cards + a patch-rate progress bar + per-host summary grid, and export to Excel/CSV/JSON/HTML. Long-running work (ping sweep, DNS+ping resolve, AD lookup, WMI last-user probe) runs through RunspacePool-based parallel scriptblocks; results stream back into grids and the log, with confirmations and outcome dialogs surfaced via a custom WptDialog. Secondary tabs reuse the same shell for Remediation Plan, Patch Cross-Ref (before/after scan compare), Weekly Export, Dirty 30 Triage (AD + last-user lookup with HTML report), CORA Vulnerabilities, and Future Target IPs.

# J.A.N.E.T. Reports Tool -- UI/UX Rebuild Spec

Source: `X:\J.A.N.E.T\Tools\ReportsTool_2.14.6.ps1` (window title declares v2.14.0). This spec describes the **frontend and run experience** so it can be rebuilt as a pure-PowerShell web-local app. The engine is re-forked separately; named entry points are listed for wiring.

## 1. Window + Navigation Layout

**Shell.** One main `Form` ("J.A.N.E.T. Reports Tool v2.14.x -- ACAS & Patch Cross-Reference"), 1400x950, min 1200x800, CenterScreen, dark background, custom dark title bar (`Set-WptDarkTitleBar`). Three docked regions:

- **Top bar** (Dock=Top, height 64, TitleBar color): gold 13pt-mono title "J.A.N.E.T. Reports Tool", grey subtitle "Joint Administration and Network Execution Toolkit", a 2px gold accent stripe along the bottom edge, and a **Close Tool** button (Danger red, top-right, re-anchored on resize). Closing is single-egress: the button calls `Set-JanetAllowClose $true` then `$f.Close()`; a FormClosing guard cancels every other close origin (the window X).
- **Sidebar** (Dock=Left, width 180): a vertical stack of flat nav buttons (one per section, 170x38, left-aligned text, hand cursor). Clicking a button highlights it (SidebarActive bg, gold text, bold) and de-highlights the rest, then toggles `$global:TabPanels[name].Visible` so only the matching content panel shows and `BringToFront()`s it; certain tabs fire their `Refresh-*` on activation. Below the buttons sits the **activity log** (see 3). This is the navigation model -- NOT a WinForms TabControl.
- **Content area** (Dock=Fill, 10px padding): hosts one full-size `Panel` per section, all `Visible=$false` except the active one.

**Section order (rebuild left-rail order exactly):** Start, ACAS Import, Remediation Plan, Patch Cross-Ref, Weekly Export, Dirty 30 Triage, CORA Vulnerabilities, Future Target IPs, Dashboard, Export.

Purpose of each: **Start** = landing/help. **ACAS Import** = the primary triage workspace (import, view toggle, filter/search, findings grid, mark actions). **Remediation Plan** = per-app (Chrome/Edge/Office/Defender/KB/Other) rollups of hosts behind target versions, with % of fleet. **Patch Cross-Ref** = load two scans (baseline + comparison) and diff them. **Weekly Export** = split a monthly ACAS_Calculations workbook into per-week summary cards (NIPR/SIPR toggle). **Dirty 30 Triage** = ingest a Tenable "Dirty 30" list and resolve each host against AD + last-logged-on user. **CORA Vulnerabilities** = CORA brief view + HTML brief. **Future Target IPs** = resolve a hostname CSV to IPs (DNS + ping). **Dashboard** = compliance metrics. **Export** = report outputs.

## 3. The Run Model + Activity View (preserve this)

**Activity log.** `New-OutputBox` builds a read-only RichTextBox (ConsoleBg, gold text, 10pt Cascadia Mono, no border) docked at the bottom of the sidebar so it persists across every tab. `Log($t)` prepends `[HH:mm:ss]`, AppendText + CRLF, then `SelectionStart=Length; ScrollToCaret()` to auto-tail; it also calls `Write-DebugLog` -> on-disk `Logs\ReportsTool_<user>_<timestamp>.log`. Rebuild as a fixed console pane fed by a single append-line helper that also persists server-side.

**Launching an operation.** Each action is a button `Add_Click`. Expensive/destructive ones first confirm via `[WptDialog]::Show(msg,title,'YesNo'|'OK', 'Warning'|'Question'|'Error'|'Information')` -- a themed modal (FixedDialog, 3px accent stripe, gold header, OK/Cancel styled buttons) returning a DialogResult string. "Mark Patched" instead calls `Show-PatchedByDateDialog` (Patched-By defaulting to `$env:USERNAME`, Patched-Date defaulting to `yyyy-MM-dd HH:mm`, returns `@{OK;By;Date}`). Empty-state guards (e.g. "Select one or more rows first.", "No findings to export.") short-circuit with an info/warning dialog.

**Parallel execution.** Per-host network work uses `[RunspaceFactory]::CreateRunspacePool(1, MaxConcurrent)` (32 for ping/DNS, 16 for WMI). Each host gets `[PowerShell]::Create()` with a scriptblock (Ping.Send; DNS+ping; AD query; or WMI `StdRegProv` `GetStringValue` of `LastLoggedOnUser`), `BeginInvoke()` fires all, then results are gathered. Two gather styles: (a) blocking `EndInvoke()` loop (ping sweep -- intentionally freezes the UI ~1.5s per batch to stop users mutating `$global:HostStatus` mid-sweep); (b) a stopwatch + `Handle.IsCompleted` poll loop with `Start-Sleep -Milliseconds 100`, marking unfinished hosts `-- timeout --`. The handler `Log()`s before and after each phase and pumps `[Application]::DoEvents()` so the console updates live; engines return hashtables/PSCustomObjects that the handler writes into globals, then calls `Refresh-*` to repaint, and finishes with an outcome `WptDialog`. **There is no per-host progress bar or hard Cancel** -- bounded fast sweeps + timeout fall-through are the design; the only stop is Close Tool. For the web rebuild, stream each phase's Log lines (and ideally per-host completions) over SSE/long-poll so the console tails live, then repaint the grid.

**Results grid (ACAS).** `New-StyledGrid`: GridBg cells, gold-on-dark bold headers, FullRowSelect, ReadOnly, no row headers, `CellBorderStyle=SingleHorizontal`, purple selection. Columns + widths: Hostname(130) | PluginID(80) | Vuln Name(300) | Severity(80) | CVE(110) | Category(120) | Status(100) | Solution(260). `Refresh-AcasGrid` runs inside `SuspendLayout`/`ResumeLayout`: clears rows, re-adds filtered findings, then **colors cells** -- Severity via `Get-SeverityColor` (Critical=Danger red, High=Orange, Medium=Warning amber, Low=Cyan, Info=dim) and Status via `Get-StatusColor` (Patched=Success green, Open=Danger red, NOT OUR PATCH=Purple); rows whose Category='NOT OUR PATCH' get the whole row dimmed to TextDim with a purple Category cell. Count label updates to "Showing N of M findings [View]". Offline view sorts by Hostname,Severity. **Row semantics:** one row per (Hostname,PluginID) finding.

**Dashboard activity view.** `Refresh-Dashboard` walks all findings once to compute totals (Total/Auto-Fixable/Patched/Remaining/Not-Ours metric cards), a **patch-rate progress bar** (a fill Panel whose Width = round(patchRate% x track width), recolored Success>=90 / Warning>=50 / Danger below -- the same thresholds color the % label), three bar charts (`Refresh-BarChart` for Severity/Category/Status -- colored Panels sized to count/max), and a per-host summary grid: Hostname | Total | Critical | High | Medium | Low | Info | Patched | Open | Not Ours | Patch Rate, with each cell colored by value (criticals red, patched green, not-ours purple, patch-rate by threshold).

**Dirty 30 activity view.** Tiles update (Parsed/Active/Stale/NotFound/TopSquadron), squadron chips rebuild, and the grid colors by Status (Active/Stale/Not Found) with last-user marker tokens `-- offline --` / `-- timeout --` / `-- error --` for unreachable hosts. After lookup+probe the polished `Render-Dirty30Html` report auto-opens (the in-grid view is a quick preview).

## 4. Targets / Credentials / Shared State

Host lists are derived, not entered: `Get-AcasHostList` returns sorted unique hostnames from findings; `Get-AcasFindingIndex` builds a `Hostname|PluginID -> finding` map for O(1) mark/undo. Future/Dirty30 ingest their own host lists from CSV/PDF. **Credentials:** none captured -- all probes run as the current interactive user (Ping, DNS, AD, and WMI `StdRegProv` all use ambient auth). The web rebuild should run engine calls under the server process identity or accept an optional cred. **Shared cross-tab state** lives in `$global:*` collections: `AcasFindings`, `HostStatus` (Hostname->Online/Offline), `ActiveView`, `FutureTargets`, `Dirty30Hosts`/`Dirty30AdResults`/`Dirty30LastUserMap`/`Dirty30ActiveFilter`, plus `RemediationStatus`, `TargetVersionOverrides`, and `NetworkDeviceCount` (persisted to `%LOCALAPPDATA%\JANET\reports_network_size.txt`). Importing/triaging on ACAS Import updates the Dashboard, Cross-Ref and Remediation views via their Refresh functions. Patched-By/Date metadata is stamped onto findings (`PatchedBy`/`PatchedDate`). State is session-only except network size and the JSON save/load round-trip.

## 6. UX Details + Visual Theme

**Theme:** dark, aliased from a shared "WPT" UI kit -- Background near-black, Sidebar/Surface dark greys, TopBar/TitleBar darkest, gold accent `#DAB452` (Accent2) for titles/headers/grid headers, primary purple `#8C64DC` (Accent1) for Import/primary actions, plus Success green, Warning amber, Danger red, Cyan, Orange (High severity), and severity/status color maps above. **Fonts:** Cascadia Mono throughout -- Title 13pt bold, section eyebrow headers 9pt mono bold, nav 9pt mono (bold when active), body 10pt, console 10pt mono, card values 22pt mono bold. **Helpers to replicate:** `New-StyledButton` auto-picks black or near-white text by luminance and lightens bg +30 on hover/+50 on press; buttons are flat, borderless, hand-cursor. **Details to preserve:** the gold accent stripe under the top bar and atop cards/dialogs; the numbered 1-5 Quick-Start welcome card empty-state; live counts baked into the view-toggle button captions; debounced search; selection-action vs "Mark All Visible" batch-action pairing; timestamped default export filenames (`*_yyyyMMdd_HHmmss`); outcome dialogs that summarize counts; and the guarded single-egress Close Tool button.
